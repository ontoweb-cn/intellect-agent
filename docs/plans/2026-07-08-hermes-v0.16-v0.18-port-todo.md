- 全量 `scripts/run_tests.sh` 通过；涉及 Rust 的任务另跑 `cargo test`；
- 新增 slash 命令走 `intellect_cli/commands/registry.py` 中央注册表；
- 新增配置键覆盖三条 config loader（`load_cli_config` / `load_config` / gateway 直读）；
- 新增持久化 schema 在 Rust 层落地，Python 仅薄封装；
- 不引入无上界依赖；不破坏 prompt caching。

## Phase 2 — P1 上（后台委派 + /learn）

### [HP-201] ⬜ [SPIKE] CLI 表面完成回流验证（HP-202 前置）

**设计依据**: 评审修订 2 | **规模**: ~1 天
**内容**: 验证 CLI 同步 REPL 下后台完成事件在"下一次输入前 drain"的可行性与体验
（复用 terminal 后台进程通知的既有路径做原型）。输出一页结论：可行方案 / 降级方案
（CLI 仅 `/bg` 主动查询）。

### [HP-202] ⬜ 后台委派注册表（Rust）+ `delegate_task(background=true)`

**设计依据**: §5.3 | **规模**: 本轮最大单项，~1–2 周 | **依赖**: HP-201
**变更**:
- [ ] `rust-core/src/delegation.rs`（新）：`DelegationRegistry`（句柄分配、状态迁移、完成队列 drain），模式对齐 `PlatformRetryScheduler`
- [ ] `intellect_rust.py`：导出注册表符号
- [ ] `tools/async_delegation.py`（新）：Python 薄封装 + 子代理线程管理
- [ ] `tools/delegate_tool.py`：schema 增加 `background: bool = false`；leaf 限制不变；schema 描述保留"跨回合持久用 cronjob/terminal"指引
- [ ] 并发受 `delegation.max_concurrent_children` 约束（后台 + 同步共享同一配额）
- [ ] Gateway 回流：走 `notify_on_complete` 同一已验证路径，**绕过双重消息 guard**（见 AGENTS.md 陷阱条目）
- [ ] CLI 回流：按 HP-201 结论实施
- [ ] 中断语义（评审定案）：父 `/stop` 不级联取消；`/bg cancel <id>` 显式取消
**验收**: `cargo test` 注册表状态机全覆盖；扇出（3 并发）结果合并为单一整合回合的端到端测试；
gateway 下 agent 运行中完成事件不丢失、不与 pending 消息队列死锁。

### [HP-203] ⬜ `/bg` slash 命令

**设计依据**: §5.3 | **规模**: ~1 天 | **依赖**: HP-202
- [ ] CommandDef（CLI + gateway）：列表 / 详情 / cancel
- [ ] gateway 表面复用 `display.background_process_notifications` 分级

### [HP-204] ⬜ `/learn` 技能蒸馏

**设计依据**: §5.5 | **规模**: ~3–4 天 | **依赖**: 无（与 HP-202 并行）
**变更**:
- [ ] `agent/learn_prompt.py`（新）：蒸馏 prompt 构建（会话摘要 + 工具序列 + 结果 → SKILL.md）
- [ ] 蒸馏走 `auxiliary_client`，配置键 `auxiliary.learn`
- [ ] 落盘走 `skill_manage` 路径，provenance `created_by: "agent"` / origin `learn_command`（自动进 curator 生命周期）
- [ ] 首版交互：生成 → 展示 → 用户确认保存
- [ ] CommandDef `/learn [名称]`（CLI + gateway）
- [ ] （可选）`rust-core/src/tool_utils.rs` 增加 `validate_skill_frontmatter_rs`（description ≤60 字符等技能规范校验）
**验收**: 生成的 SKILL.md 通过技能规范校验；curator 能识别其 provenance；
拒绝保存时无副作用。

## Phase 3 — P1 下（验证证据 + MoA + 蓝图）

### [HP-302] ⬜ MoA 虚拟 provider（`moa/<preset>`）

**设计依据**: §5.6 | **规模**: ~1 周 | **依赖**: HP-301
**变更**:
- [ ] `plugins/model-providers/moa/`（新）：ProviderProfile 注册，模型目录来自 preset
- [ ] `agent/moa_loop.py`（新）：N 参考模型并行 + 聚合器；解除 OpenRouter 硬绑定
- [ ] `agent/moa_trace.py`（新）：分层轨迹入会话日志（Rust `SQLiteBackend` 既有路径）
- [ ] `intellect_cli/moa_config.py`（新）：preset 配置（`moa.presets.*`）
- [ ] 按 HP-301 结论实现拦截分流；带 tool-calling 场景检测到 `moa/` 报错并提示
- [ ] token 用量并入 Rust `TokenAccumulator`；MoA 模型豁免二级路由（fallback / smart routing）
- [ ] CommandDef `/moa`（preset 列表/切换）
- [ ] 现有 `mixture_of_agents` 工具标记 legacy（文档指向虚拟 provider，不删除）
- [ ] 成本明示：调用前 UI 提示 N+1 次调用放大（评审定案 Q3：预算联动为可选后续）

### [HP-303] ⬜ 验证证据台账（Rust）+ verify-on-stop + `/goal` 契约

**设计依据**: §5.4 + 评审修订 3 | **规模**: ~1–1.5 周 | **依赖**: 无
**变更**:
- [ ] `rust-core/src/verification.rs`（新）：`verification_evidence` 表读写（复用 `SQLiteBackend`）+ 验证命令分类正则表（pytest/cargo test/npm test/go test/make check…）
- [ ] **schema 迁移与 `intellect_state.py` 版本机制协调**（当前 v15，统一 bump，禁止旁路建表）
- [ ] `agent/verification_evidence.py`（新）：薄封装；写入点 = terminal 验证类命令完成 + `rust_file_mutation_landed` 通过
- [ ] `agent/verification_stop.py`（新）：pre-final-response 检查——本回合有代码修改且无证据时注入 nudge
- [ ] `agent/conversation_loop.py`：**仅 2 个挂钩点**（post-tool-call 记录 / pre-final-response 检查），fail-open
- [ ] `intellect_cli/goals.py`：judge prompt 注入证据摘要；`/goal` 语法支持完成契约
- [ ] `webui/api/goals.py`：goals 页展示证据列表
- [ ] 配置门控 `agent.verification.enabled`（**默认 false**，灰度一个 minor 版本后翻转——评审定案 Q2）
**验收**: 台账故障不阻塞回合（fail-open 测试）；证据分类 `cargo test` 覆盖；
goal judge 在有/无证据下的判定对照测试；关闭门控时 conversation_loop 零行为变化。
