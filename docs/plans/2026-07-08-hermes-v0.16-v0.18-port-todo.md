**背景**: Intellect cron 为**进程内 tick**（`cron/__init__.py:14`：gateway 每 60s 敲一次）；scale-to-zero 停机后 tick 死亡 → 停机窗口内定时任务不触发。Chronos 从**外部**按时触发到期任务，是 scale-to-zero 下 cron 保活的正解。
| ID | 内容 | 估时 |
|----|------|------|
| HP-408a | cron provider 抽象：`cron/scheduler.py` tick 与外部触发解耦；配置 `cron.provider` = `builtin` \| `chronos` | 1d |
| HP-408b | `plugins/cron_providers/chronos/` 插件骨架 + 配置 schema（三条 config loader） | 1d |
| HP-408c | gateway 鉴权 `/cron/run-due` 触发端点：外部 Chronos ping → socket-activate → 跑到期任务 | 1d |
| HP-408d | 幂等/去重：复用文件锁防重复 fire；与 builtin tick 互斥并存 | 0.5d |
| HP-408e | 与 HP-406 socket-activation 唤醒对齐；`scale_to_zero + cron` 校验要求 chronos provider | 0.5d |
| HP-408f | 测试（外部触发 mock + 去重 + provider 切换）+ 文档（Chronos 服务配置/鉴权） | 1d |

**验收**: scale-to-zero 下定时任务不丢；`builtin` provider 零回归；外部触发鉴权且幂等（不重复 fire）。
